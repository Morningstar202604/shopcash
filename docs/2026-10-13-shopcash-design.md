## 一、产品定位

给单个实体门店使用的 Windows 单机收银 + 收款记账软件。一个便携目录双击即用，数据全部落在本机 SQLite。**钱只进商家自己的微信/支付宝直连商户号，软件不经手任何资金。**

## 三、架构

```
Tauri(Rust) 壳 ── 窗口 / 托盘 / 自启 / 健康看门狗 / 拉起并回收 sidecar
      │ spawn(--port --data-dir)
      ▼
NestJS sidecar ── 127.0.0.1:动态空闲端口 ── 提供 REST API + 静态前端
      │
      ▼
Prisma + SQLite(WAL) ── data/app.db
      ├── keys/master.key（机器指纹派生，加密渠道凭据）
      ├── backups/（每 30 分钟快照，保留 7 天）
      └── logs/（结构化 JSON，按天滚动）
```

无 Redis、无 Docker、无外部服务。并发控制改为：进程内 Mutex（订单号粒度）→ SQLite 事务 → 条件原子更新 `UPDATE ... WHERE status IN (...)` → `orderNo`/`idempotencyKey` 唯一约束。

## 四、订单状态机（一期不可绕过的硬规则）

```
PENDING → PAYING → PAID → REFUNDING → REFUNDED
   ↓         ↓
 CLOSED   EXCEPTION ←── 已 CLOSED 后查到支付成功 / 金额不符 / 回调异常
```

1. 渠道返回金额与订单金额**必须完全相等**才允许置 PAID，不等一律 EXCEPTION
2. 已 CLOSED 的订单事后查到成功，**只能进 EXCEPTION 走人工**，绝不自动入账
3. 每 5 分钟扫描超时未支付订单，关单前先做最后一次主动查单
4. 到账三层兜底：可选回调 → 主动查单退避轮询（3s/10s/30s/2min/5min，最长 15min）→ 每日账单对账

## 五、一期模块与角色

P0：首启向导（强制设店主口令，不留默认账号）／渠道配置中心（mock+真实凭据表单+配置自检）／收银台（含现金收款）／订单状态机与三层兜底／订单簿与 CSV 导出／退款（店员可发起、店主确认）／班次与交接班（含备用金与实点差额）／日对账与差异／备份恢复／审计哈希链与链校验／异常工作台／员工与权限／诊断信息包。

角色：OWNER（全部）与 CASHIER（收银、本班次查询、发起退款、本班交接）。
二次确认清单：退款、恢复备份、修改渠道凭据、异常单结案、删除订单备注 —— 需再次输入店主口令。

## 六、容灾

RPO 30 分钟、RTO 约 30 分钟。断电靠 WAL 事务回滚 + 开机首轮查单补偿。磁盘写满顶部红色横幅并禁止新建订单。系统时间偏差 >2 分钟弹提醒。应急手记模式：软件彻底不可用时离线记录笔数金额，恢复后补录进 EXCEPTION 人工结案。
